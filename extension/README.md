# 이지서치 크롬 확장

`c:\Ai\naver_keyword` 사이트 확장 계획 중 "2. 원클릭 접근"(v0.1.0)과 "1. 실시간 오버레이" 일부(v0.2.0, 에디터 한정)를 구현했습니다.

## 기능

### 원클릭 접근

- **우클릭 조회**: 아무 페이지에서나 텍스트를 선택하고 우클릭 → "이지서치로 검색량 조회" → 데스크톱 알림으로 PC/모바일/합계 검색량이 바로 뜸.
- **주소창 검색**: 주소창에 `ez ` 입력 후 키워드 입력, Enter → 같은 방식으로 알림 표시.
- **팝업**: 툴바 아이콘 클릭 → 검색창 + 결과(연관 키워드 최대 10개 포함) + 최근 검색 20개 + 즐겨찾기.
- 알림을 클릭하면 이지서치 사이트로 이동(연관 키워드·CSV 등 더 자세한 내용은 사이트에서).

### 네이버 블로그 에디터 통합 (⚠️ 선택자 미검증 — 아래 참고)

- `/write`에서 글을 생성한 뒤 "확장으로 보내기" 버튼 클릭 → 네이버 블로그 아이디가 저장돼 있으면 에디터 탭이 자동으로 열림(v0.4.0). **제목·본문 자동 삽입은 2026-08 실측 결과 안 되는 것으로 확인됨** — `simulatePaste`(합성 paste 이벤트)·`document.execCommand` 둘 다 시도해봤지만 SmartEditor가 스크립트로 만든 입력은 받아들이지 않고 사람이 직접 누른 Ctrl+V만 받아들임(브라우저의 `isTrusted` 신뢰 이벤트 구조상 확장이 우회하기 어려운 벽으로 보임). 그래서 v0.4.7부터 목표를 "완전 자동"에서 **"Ctrl+V 최소화"**로 낮춤 — 제목란에 커서를 미리 갖다두고(클립보드엔 이미 서식 포함 내용이 복사돼 있음), 제목에 Ctrl+V를 누르면 커서가 자동으로 본문란으로 넘어가서, 클릭 없이 **Ctrl+V 두 번만** 누르면 제목·본문이 다 채워짐. 그래도 안 먹으면 우측 하단에 "이지서치 초안 붙여넣기" 버튼이 남아 재시도 가능. **v0.5.0에서 `chrome.debugger`(CDP)로 진짜 자동 입력을 한 번 시도했으나, 사용 직후 브라우저가 반복적으로 꺼지는 안정성 문제가 실사용에서 보고돼 v0.5.1에서 완전히 되돌림** — `debugger` 권한도 제거했음. 원인 불명이라 이 접근은 다시 시도하지 말 것.
- **사진·AI이미지도 자동 삽입됨(v0.3.0)** — 사용자가 사진 업로드/AI 이미지 생성을 하면, 확장이 네이버의 실제 이미지 업로드 API로 재업로드한 뒤 그 결과 URL을 본문에 끼워 넣음(§CLAUDE.md 17.5). **단, 이 에디터에서 사진을 최소 1장은 직접 업로드해본 적이 있어야 함** — 업로드 API 주소가 글쓰기 세션마다 새로 발급되는 서명된 URL이라, 확장이 스스로 만들어낼 수 없고 실제 업로드가 한 번 일어나는 걸 관찰해서만 알아낼 수 있음. 스톡 이미지(Pixabay)는 이번 범위에 포함 안 됨 — 여전히 기존처럼 안내 문구만 남음.
- 태그 입력창에 타이핑하면(디바운스 500ms) 옆에 월간 검색량 배지가 뜸.
- **`extension/src/content-editor.js`의 `SELECTORS`는 2026-08에 제목·본문·태그 셋 다 실측 확인됨**(사용자가 개발자 도구로 실제 DOM 캡처) — 제목은 `.se-section-documentTitle .se-module-text.se-title-text`, 본문은 `[data-a11y-title="본문"]`, 태그는 `#fake-input`(class는 CSS Modules 해시가 있어 `[class*="fake_input__"]`로 부분일치). **다만 태그 쪽은 확실하지 않음** — `#fake-input`에 `tabindex="-1"`·`aria-hidden="true"`가 붙어 있어서 실제 타이핑 지점이 아니라 내부용 더미 input일 수 있음(옆의 `tag_input_wrap__` span 내부가 진짜일 가능성 — 캡처 화면에 안 보여서 미확정). 태그 검색량 배지가 안 뜨면 이 부분부터 다시 확인할 것. 네이버가 SmartEditor 마크업을 바꾸면 셋 다 다시 깨질 수 있으니, 또 "입력창을 찾지 못했다"는 메시지가 뜨면 같은 방식(개발자 도구로 우클릭 → 검사)으로 재확인할 것.
- **SmartEditor 본체는 `mainFrame`이라는 iframe 안에 있음(2026-08 실측 확인)** — 최상위 페이지가 아니라 주소 패턴 `PostWriteForm.naver`(`blog.naver.com` 도메인)인 iframe 안에서 렌더링됨. `manifest.json`의 `content_scripts`가 `all_frames: true`라 그 iframe에도 스크립트는 이미 주입되지만, 자동 삽입 로직을 최상위 프레임에서만 돌게 제한했던 적이 있었는데(프레임 경쟁을 막으려던 시도) 그게 오히려 자동 삽입을 완전히 막고 있었음 — 그 제한은 되돌렸음(모든 프레임이 독립적으로 시도, `SELECTORS`가 충분히 구체적이라 관련 없는 프레임은 그냥 조용히 못 찾고 넘어감).

## 로컬에서 테스트하기

1. `extension/src/config.js`의 `API_BASE_URL`을 로컬 개발 서버로 바꿉니다: `http://localhost:3000`
2. `npm run dev`로 Next.js 서버를 띄웁니다.
3. Chrome에서 `chrome://extensions` → 우측 상단 "개발자 모드" 켜기 → "압축해제된 확장 프로그램을 로드합니다" → 이 `extension/` 폴더 선택.
4. 아무 페이지에서 텍스트 선택 후 우클릭, 또는 주소창에 `ez 키워드` 입력해서 확인.

**배포 전에 `config.js`를 다시 `https://ezzsearch.com`으로 되돌릴 것.**

### 권한 사용 이유 (Developer Dashboard의 권한별 정당화 입력란에 사용)
| 권한 | 사용 이유 |
|---|---|
| `contextMenus` | 우클릭 메뉴에 "이지서치로 검색량 조회" 항목을 추가하기 위해 사용 |
| `storage` | 최근 검색 기록·즐겨찾기, 웹사이트→확장 간 초안 전달용 임시 데이터를 브라우저에만 저장하기 위해 사용(외부 전송 없음) |
| `notifications` | 조회한 키워드의 검색량 결과를 데스크톱 알림으로 보여주기 위해 사용 |
| `webRequest` | 네이버 블로그 에디터의 이미지 업로드 요청 주소를 관찰(요청 차단·변경 없음)해서, 사용자가 올린 사진을 같은 방식으로 자동 업로드하기 위해 사용 |
| `unlimitedStorage` | 여러 장의 사진을 base64로 임시 저장할 때 기본 저장 용량(5MB)을 넘을 수 있어 사용 |
| `host_permissions: ezzsearch.com` | 자체 API(`/api/extension/keyword-lookup` 등)를 호출해 검색량을 조회하기 위해 사용 |
| `host_permissions: blog.upphoto.naver.com, blogfiles.pstatic.net` | 네이버 블로그 에디터에 사진을 자동 업로드하기 위해 사용 |
| `host_permissions: blog.naver.com` | 네이버 블로그 에디터 페이지에 초안 붙여넣기 버튼과 태그 검색량 배지를 표시하기 위해 사용 |

### 데이터 사용 공개(Privacy practices 탭 체크박스)
- 개인 식별 정보(이름, 이메일 등): 수집 안 함
- 웹사이트 콘텐츠(사용자가 선택한 텍스트): 검색량 조회 목적으로만 이지서치 서버에 전송, 저장하지 않음(서버에서 최대 10분 캐시 후 자동 삭제)

1. Chrome Web Store Developer Dashboard(https://chrome.google.com/webstore/devconsole) 접속 → 처음이면 Google 계정으로 1회 $5 등록.
2. "새 항목 추가" → 위에서 만든 zip 업로드.
3. 위 "스토어 등록 정보"·"자세한 설명 초안"·"권한 사용 이유"를 각 입력란에 붙여넣기.
4. 스크린샷 최소 1장(1280×800 또는 640×400) 필요 — 팝업 화면, 우클릭 조회 알림, "확장으로 보내기" 결과 화면 등을 실제로 캡처해서 준비할 것(이 부분은 실제 브라우저 사용 화면이 필요해 자동화 불가).
5. 심사 제출 — 보통 검토에 며칠 걸림. `webRequest`·`host_permissions` 조합은 리뷰어가 더 자세히 볼 수 있어, 위 권한 사유를 최대한 구체적으로 남겨둘 것.
- **네이버 블로그 에디터 선택자(`content-editor.js`의 `SELECTORS`)는 실제 브라우저에서 재검증 필요** — 위 "네이버 블로그 에디터 통합" 항목 참고. 안 먹으면 클립보드 복사(수동 Ctrl+V)로는 항상 동작하도록 이중 안전장치를 넣어뒀지만, 자동 삽입 자체는 실사용 확인 전까지 신뢰하지 말 것.
- **이미지 업로드 API(`blog.upphoto.naver.com`)는 비공식·비문서화 API** — 사용자가 실제 캡처한 요청 1건을 그대로 흉내 낸 것이라, 네이버가 이 엔드포인트를 바꾸면 예고 없이 깨질 수 있음. 종단간(진짜 사진 자동 삽입까지) 검증은 아직 안 됨 — API 구조(요청/응답 형식)만 실측 확인했고, 실제로 확장 안에서 호출해서 삽입까지 되는지는 사용자가 직접 테스트 필요.
- 검색결과 페이지(search.naver.com) 연관검색어 옆 배지, 스마트스토어·플레이스 오버레이는 이번 범위 밖 — 네이버 에디터 태그 입력창 하나로 먼저 검증한 뒤 확장할지 결정.
- 3번(자동 모니터링)은 이번에도 포함 안 됨 — 지금 무제한(스로틀 없음) 검색광고 API 호출 패턴을 확장 트래픽이 어떻게 바꿀지 먼저 지켜본 뒤 진행하는 게 안전함.

## 백엔드

`POST /api/extension/keyword-lookup` — 이 확장 전용 경량 엔드포인트. 웹사이트의 `/api/search`(Notion 세션 저장까지 하는 무거운 흐름)와 의도적으로 분리되어 있음. 10분 TTL 캐시를 씌워서 같은 키워드 반복 조회가 네이버 검색광고 API를 다시 때리지 않게 함 — 자세한 이유는 그 라우트 파일의 헤더 주석과 `CLAUDE.md` §17 참고.
